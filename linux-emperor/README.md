# linux-emperor

Kernel packaging inputs for Emperor Linux: a reviewed config fragment, an
ordered patch series, and the rebase workflow. The base is mainline
7.4-rc3 during bring-up; released ISOs should use a 7.4.y stable tag.

## Layout

```text
config/emperor.fragment  Reviewed CONFIG_* policy, merged over x86_64_defconfig
config/defconfig         Generated by `make savedefconfig`; commit it
patches/series           Ordered patch filenames, applied with -p1
patches/apply.sh         Applies patches/series to a clean kernel tree
```

## Generate and check the config

```sh
make O=out x86_64_defconfig
scripts/kconfig/merge_config.sh -m -O out out/.config config/emperor.fragment
make O=out olddefconfig
make O=out savedefconfig
cp out/defconfig config/defconfig
```

CI should run the same sequence and fail if `out/defconfig` differs from the
committed `config/defconfig`.

## Package recipe wiring

The package format is not fixed yet. Both examples below use the same
primitives: apply patches, merge the fragment, run `olddefconfig`, build.

PKGBUILD:

```bash
prepare() {
  cd "linux-${_srcver}"
  "$srcdir/patches/apply.sh" "$PWD" "$srcdir/patches"
}

build() {
  cd "linux-${_srcver}"
  make O=out x86_64_defconfig
  scripts/kconfig/merge_config.sh -m -O out out/.config "$srcdir/config/emperor.fragment"
  make O=out olddefconfig
  make O=out -j"$(nproc)" bzImage modules
}
```

Ebuild:

```bash
src_prepare() {
  default
  "${FILESDIR}/patches/apply.sh" "${S}" "${FILESDIR}/patches"
}
```

## Rebasing

Keep patches as git commits on an `emperor/7.x` branch:

```sh
git switch -c emperor/7.5 v7.5-rc1
git rebase --onto v7.5-rc1 v7.4-rc3 emperor/7.4
git range-diff v7.4-rc3..emperor/7.4 v7.5-rc1..emperor/7.5
git format-patch --zero-commit --no-signature -o patches v7.5-rc1..HEAD
ls patches/*.patch | xargs -n1 basename | sort > patches/series
```

Re-run the config merge and boot tests after every rebase. A patch is only
kept if it has a documented reason, an upstream reference, and an owner.
